Action inventory

What the engine runs when it reaches a target. Two rows are consent-gated: command injection and web-shell upload never fire without --destructive.

Recon

  • Passive reconcrt.sh and Wayback feeds mapped before the first packet touches the target
  • Crawlbreadth-first discovery of pages, forms and script files, same-origin only
  • Fuzzknown paths and parameter sets probed; 404-baseline aware so soft-404 noise stays out
  • Port scanconcurrent sweep across the host's interface addresses

Probes — detection

  • XSScanary-tagged reflection; a claim needs an executable context the baseline cannot echo
  • SQL injectionboolean-differential and time oracle gated 2-of-2; errors confirmed against a neutral round
  • Local file inclusionstructural file records diffed against a no-payload baseline, then read for content
  • GraphQLintrospection and field exposure checked against the schema the endpoint reveals
  • S3 bucketscandidate enumeration and readable-bucket confirmation, evidence above name collisions

Exploitation & signals

  • Login brutedifferential verdict against a junk-credential baseline — the page lying about success is filtered out
  • JWT forgealg=none and common-secret signing; access requires more than an accepted token shape
  • OOB callbacksblind SSRF/SSTI/XSS sink with a reachability verdict — an unreachable sink says so instead of promising

Consent-gated do not fire without --destructive

  • Command injectionquoted-marker probe; uid= output from a real execution — nothing else — releases the verdict
  • Web shell uploadupload accepted is reported as medium; a deployed shell is claimed only when its marked probe executes

The verdict system

The report's structure forces honesty: findings can only be filed by execution. Signals and untested chains are recorded, but they never inflate the risk score.

Risk, read honestly

Risk sums executed severity. Observed signals inform where to look; hypotheses describe what the engine would run. The report separates the three, so a client reading it knows exactly what was claimed, and on what proof.

After the audit phase, reports are re-cut to this discipline: keyword-only claims, body-length file reads and public-page token acceptance no longer exist.

Install

Fail-closed: the installer resolves one tag, verifies SHA256 and the pinned GPG key, and aborts with nothing installed when any check refuses.

# Linux / macOS — fail-closed installer
curl -sfL https://raw.githubusercontent.com/NICE-DEV226/nice-Scan/main/scripts/install.sh | sh
# Windows — PowerShell 7+
irm https://raw.githubusercontent.com/NICE-DEV226/nice-Scan/main/scripts/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy RemoteSigned -File install.ps1
# Pinned tag — no @latest, no main HEAD
go install github.com/NICE-DEV226/nice-Scan/cmd/nice_scan@v0.2.1

Usage

Four frames for the same engine — pick the one the engagement asks for.

  1. nice_scan hack example.com -R report.html

    Full engagement. Recon, probes, chaining and extraction in one run, with the verdict-ordered report at the end.

  2. nice_scan scan example.com -i

    Live dashboard. Streaming findings and progress while the scan talks, for monitoring a longer sweep.

  3. nice_scan exploit https://example.com --login --idor 1-100

    Targeted exploitation. Run selected modules against endpoints you already know. --register is refused without consent.

  4. nice_scan hack target.com --timeout 30s --destructive

    Consented run. Time-boxed, and with the flag only the operator types when written permission covers state changes — command and shell modules included.

Trust the binary before you run it

Nothing here is marketing posture. Items that are not shipped are marked as such.

Checksums + signature

  1. Every release publishes checksums.txt; GPG-signed when signing keys are configured.
  2. The installer pins fingerprint 4CE4…A4DB from keyserver.ubuntu.com.
  3. Mismatched key or unmatched checksum aborts, nothing executes.
sha256sum --check checksums.txt --ignore-missing
gpg --verify checksums.txt.sig checksums.txt

Provenance & SBOM

  1. GitHub build-provenance attestations are emitted per release — releases cut after 2026-10-24, nothing retroactive.
  2. Cosign keyless bundles arrive alongside the manifest.
  3. An SPDX SBOM ships in the release assets.
gh attestation verify nice_scan -R NICE-DEV226/nice-Scan

Audit the code instead

  1. go install anchors strictly to a resolved tag.
  2. Cloning a pinned tag removes every trust intermediary at once.
git clone --branch v0.2.1 https://github.com/NICE-DEV226/nice-Scan.git

Run only against assets you own or where you hold explicit written permission. nice_scan records consent for state-modifying actions; the operator still carries responsibility for where it points.
